Website maintenance

Content
- Papers: _data/researcher.json. Add an object to papers[].
  Required fields: title, url, authors, venue, year, category, links.
  category is Preprint or Publication. Use an empty url for an unlinked paper.
  Optional journal is the bold journal name and must match the start of venue.
  Publications are sorted by year descending; ties preserve data order.
  The homepage and /publications/ use the same data.
- Introduction and research interests: _layouts/researcher.html.
- Education and experience on the website: _includes/researcher/cv.html.
- Profile links and Google Analytics ID: _config.yml.
- Blog: _research_blog/*.md. Follow _docs/BLOGGING.txt.
- Styles: assets/css/researcher.css.
- Portrait: images/profile_new.jpg.
- CV PDF: edit cv.tex and regenerate out/cv.pdf. The web CV is separate.
- Slides: files/*.pdf. Keep existing URLs stable.

Local preview
  bundle install
  bundle exec jekyll serve --config _config.yml,_config.dev.yml

Production validation
  JEKYLL_ENV=production bundle exec jekyll build --safe

Check /, /publications/, /cv/, /blog/, /blog/feed.xml, /feed.xml,
/sitemap/, /sitemap.xml, and /404.html. Check the redirects /about/,
/about.html, and /resume. Confirm CV and slide links and a narrow viewport.

Structure
The site uses two layouts: researcher and research-note. Legacy AcademicPages
sample collections, pages, Sass, JavaScript, fonts, images, and generators have
been removed. Their old URLs are intentionally no longer generated.
The only image in images/ is the current portrait; the SVG favicon is stored
in assets/images/. Future blog figures may be added under images/blog/.
RSS is generated from published research blog articles at /blog/feed.xml and
/feed.xml. The XML sitemap is generated by jekyll-sitemap.

CV source and LaTeX intermediate files remain local but are excluded from the
published output. Existing tracked intermediate files are left untouched to
preserve local CV work. Google Analytics runs only in production.

Publishing
GitHub Pages publishes master / (root). Changes pushed to master are published
automatically. Review changes before committing and pushing.
